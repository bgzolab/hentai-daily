# 技术栈选择与规范

## 前置要求（最高优先级）

1. 保证项目使用最简单、最健壮的技术栈；
2. 注重模块化（多文件）和禁止单体巨文件（monolith）；
3. 写任何代码必须完整阅读设计文档 `docs/memories/@design.md`、项目架构 `docs/memories/architecture.md`（如果有数据库，包含完整数据库结构）；
4. 任何代码必须包含单元测试，且测试覆盖率尽量达到 100%；
5. 每完成一个重大功能或里程碑后，必须更新 `docs/memories/@architecture.md` 中的架构设计文档，具体要求参考文件内定义；
6. 技术栈不必可以拘泥于某个语言（2～3个，如 `python`、`shell`），允许使用脚本语言，但是需要保证效率、可读、维护与追溯性，这意味着必须选择最简、最合适的技术栈，并保证最终文件落地到项目中，保证日后可追溯 (严格禁止在 /tmp 目录黑箱操作)。
